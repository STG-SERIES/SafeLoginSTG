## Summary

SafeLoginSTG 1.0.0 is the first public/private release of the hybrid login plugin. It authenticates cracked players with passwords shown in Paper Dialogs, lets premium Mojang usernames auto-login after a one-time password setup (when the same trusted client returns), and supports switching the same username between cracked and premium clients with password challenges on each switch.

---

## What’s included in 1.0.0

### Authentication

- Mojang profile API check (`api.mojang.com/users/profiles/minecraft/{name}`)
- Cracked usernames: register once, password **every** join
- Premium usernames: register once, then auto-login on the trusted client
- Hybrid same-name flow using client cookies + premium/cracked tokens
- Auth timeout kick (`auth-timeout-seconds`, default 120)
- Unauthenticated players cannot move, chat, run commands (except blocked), interact, break/place, fight, or be targeted

### UI

- Paper Dialog **Creating a Password** (password + confirmation, Create Account / Logout)
- Paper Dialog **Login** (password, Login / Logout)
- Escape cannot dismiss auth dialogs

### Security

- PBKDF2-HMAC-SHA256 (`120000` iterations, 16-byte salt, 256-bit key)
- Storage format: `pbkdf2$iterations$salt$hash`
- No plaintext password recovery command
- YAML local store only (no MySQL)

### Admin (OP-only)

- `/SLSTG setpswd <player> <new password>`
- `/SLSTG reset <player>` — wipe account; next join is first-time signup
- Console and RCON allowed; non-OP players denied

### Permissions

| Permission | Default | Notes |
|---|---|---|
| `safeloginstg.admin` | `op` | Declared for the command; executor also checks `isOp()` |
| `safeloginstg.bypass` | `false` | Skip all auth |

## Install (v1.0.0)

1. Run Paper/Purpur **1.21.11** with Java **21+**.
2. Place `SafeLoginSTG-1.0.0.jar` in `plugins/`.
3. For hybrid cracked + premium: set `online-mode=false` in `server.properties`.
4. Start the server once to generate config.
5. Optionally edit `plugins/SafeLoginSTG/config.yml`.

### Build from this tag / tree

```bash
./gradlew build
# → build/libs/SafeLoginSTG-1.0.0.jar
```

Windows:

```bat
gradlew.bat build
```

## Config reference (v1.0.0)

```yaml
min-password-length: 4
max-password-length: 64
auth-timeout-seconds: 120
```

| Key | Type | Default | Meaning |
|---|---|---|---|
| `min-password-length` | int | `4` | Minimum password length on register / setpswd |
| `max-password-length` | int | `64` | Maximum password length |
| `auth-timeout-seconds` | int | `120` | Kick if auth not completed in time |

## Commands reference (v1.0.0)

```
/SLSTG setpswd <player> <new password>
/SLSTG setpassword <player> <new password>   # alias
/SLSTG reset <player>
```

**Access:** operator (`isOp()`), or server console / RCON.

**`setpswd`** — writes a new PBKDF2 hash for the player name (case-insensitive account key).

**`reset`** — deletes the YAML account entry (hash, modes, tokens). If the player is online, they are de-authenticated and shown the register dialog immediately.

## Auth behavior matrix (v1.0.0)

| Client / username | First visit | Later visits |
|---|---|---|
| Cracked-only name | Register dialog | Login dialog every time |
| Premium name, first ever | Register dialog | — |
| Premium name, same trusted client | — | Auto-login |
| Premium name, cracked client | — | Login every time |
| Premium client after cracked used the name | — | Login once, then auto again |
| `safeloginstg.bypass` | Auto | Auto |

## Data files (v1.0.0)

### `plugins/SafeLoginSTG/config.yml`

Generated from the jar defaults on first run.

### `plugins/SafeLoginSTG/accounts.yml`

Example shape:

```yaml
accounts:
  playername:
    hash: pbkdf2$120000$...$...
    uuid: "..."
    last-auth-mode: PREMIUM   # or CRACKED / NONE
    premium-token: "..."
    cracked-token: "..."
    created-at: 0
    updated-at: 0
```

Treat this file as sensitive.

| Piece | Implementation |

## Known limitations (v1.0.0)

1. **No ProtocolLib Mojang session handshake** — cookies distinguish clients/launchers; they are not a full online-mode proof.
2. **Shared `.minecraft` folder** between launchers can share cookies and blur cracked vs premium client detection.
3. **Mojang API outages / 429** — name is treated as cracked until cache/API recovers.
4. **Offline UUID-only backends without cookies** — hybrid same-name behavior depends on cookie support (Minecraft 1.20.5+ clients).
